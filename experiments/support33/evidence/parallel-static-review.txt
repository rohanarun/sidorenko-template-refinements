Completion proof
Fix a nonempty active pair set E' contained in the 28 allowed pairs.
Its order is the restriction of the full star order; this follows because
both are sorted by the same vertex-position key. Write B_E'(tau) for the
displayed relaxed right-hand side, including its -2|E'| term, for any
type sequence tau. A type is 111,000,001,010 or011. Its defect contribution
is respectively0,0,1,1 or2. For every missing pair insert, at that pair's
place in the full order, two consecutive vectors of type111.

The total defect and the accumulated defect before each old vector do
not change. Every old T_a count is unchanged because inserted vectors
have tau_a=ell_a-g=0. The old two vectors of a pair stay adjacent, so the
previous-vector g used at its second vector is unchanged. Every old N_a
can only increase, and every old zero-based position p can only increase.
Consequently each old nondefect term
min(N_i,N_j,T_i+T_j+[second]*lastg) does not decrease. Neither does an
old one-defect contribution N_i+N_j, nor an old two-defect contribution
N_i+N_j+p-ceil(d_previous/2).

For an inserted pair the first nondefect contribution is nonnegative.
At the second inserted vector both endpoint N counts are at least1,
and lastg=1, so its minimum is at least1. The two contributions thus
sum to at least1 while the new pair costs2 in the initial -2m term.
Each inserted pair lowers the relaxed objective by at most1. This proves
B_full(extended tau) >= B_E'(tau) -(28-m), and maximization proves the
claimed inequality.

No geometric realization of the extended sequence is asserted or needed.
The DP intentionally drops such constraints. The inserted sequence is
accepted by the relaxed transitions: T starts at zero, only defect
transitions raise it, defect never decreases, and a111 transition always
exists. Forgetting a point is lossless because it has no later occurrence;
an insertion can keep a point live longer but leaves its T value intact.
The max-defect cutoff26 cannot remove a path ending at defect<=26.

Tail proof independent of the DP
For any active support, write n1 for one-defect vectors and n2 for
two-defect vectors, so d=n1+2*n2. The existing averaging calculation gives
R <= 178 +(23/2)n1 +(67-n1-n2)n2.
Support uniformity follows as follows. The full allowed graph is connected
and has degree vector(3,6,3,6,4,2,4,4,4,6,4,6,4). For a nonempty subgraph,
add missing edges by first reaching all vertices from an existing edge,
then filling remaining edges. Every insertion has at least one previously
nonisolated endpoint, so sum(delta_i^2)-3m does not decrease. Its full-graph
value is178. The endpoint surplus is at most23. Also global k is at most
2m-n1-n2, because every defect vector is globally dependent; m<=28.
These are exactly the ingredients of the stated tail inequality.

Put t=n2. The bound is
  178 +(23/2)d +(44-d)t +t^2,  0<=t<=floor(d/2).
It is convex in t, so its maximum over the allowed integers is at an
endpoint. At t=0 it is <=33d for d>=9. If d=2t is even, the other endpoint
is <=33d exactly when t^2-t-178>=0, true for t>=14. If d=2t+1 is odd,
the condition is t^2>=313/2, true for t>=13. Hence R<=33d for every d>=27,
without a finite tail execution or reliance on the saved cap38 output.

Code review
The original source uses only standard-library parsing, exact integers,
Fractions for its separate tail formula, dictionaries and fixed graph
enumeration. run_dp has no network, subprocess, import of repository
modules, file I/O, mutation of the baseline, or external side effect.
The new driver uses runpy with a non-main name, so the original main's
output write does not execute. It invokes only allowed_pairs, star_order
and run_dp with the fixed graph and cap5 or26. Every source/data file is
SHA-pinned before and after execution. It emits one small JSON result.

The recurrence exactly matches the displayed relaxed objective. States
contain the live T tuple, previous g and accumulated d. Independent111
and dependent000 preserve T/d;001/010 increment one T and d;011 increments
both T and d by2 and contributes x-ceil(d_before/2)+N_i+N_j. The code's
(d+1)//2 is the correct ceiling. No realizability condition is required
to use a larger relaxed maximum as an upper bound. The -1 sentinel in
push/merge cannot discard a valid candidate: all pre-cost sums are
nonnegative, since reachable d<=2*x implies x-ceil(d/2)>=0. The -2m cost
is applied only after the last vector. Removing closed coordinates by
maximization is sufficient and exact for future transitions.
